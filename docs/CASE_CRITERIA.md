# Case criteria → reviewable product behaviour

The supplied case states success criteria, not a numerical weighting. This matrix is our interpretation of what a reviewer can verify; it does not claim an official score.

| Case criterion | Implemented behaviour | Review scenario / practical limit |
|---|---|---|
| Company-specific relevance | Reviewed profile, actual case-client fields, versioned exposures, regions, priorities, counterparties and separate decision roles | Compare education publisher, teaching platform and manufacturing client; CFO vs CEO. Unknown debt terms or jurisdictions remain unknown. |
| Interpretation beyond summarisation | Reported fact → confirmed company feature → conditional mechanism → decision/check → uncertainty | Open an event and follow its cited article. Suggested planning horizons are not statutory deadlines. |
| Bank expertise affects conclusions | Nine original page-indexed reports; bilingual BM25 retrieval; short reference IDs and exact selectable quotes | Manufacturing financing event links its bank view to a dated page. Unrelated education events have an explicit no-supporting-bank-excerpt label. |
| Source fidelity and synthesis | Real RSS/Atom/HTML, deduplication, full-text enrichment, citation checks, independently reviewed events and briefs | Verify originals and historical dates. OCR errors and inaccessible publisher bodies remain limitations. |
| Fresh/unseen news | Public collection and profile/market-specific source discovery; no runtime fixture generator or fixed recommended-outlet catalogue | New company → discover sources → run monitoring. Broken/challenged indexes are exposed; manual sources remain available. |
| End-to-end usable product | Verification gate, three-step onboarding, reviewed context and sources, dashboard, signals, briefs, questions, notifications | Separate guest read-only tour and password-authenticated jury account; ordinary registration requires email ownership. |
| Multi-factor analysis | Business drivers plus source facts and relevant bank context; period-based causal synthesis | Inspect sources and gaps. Sparse evidence must not become a claimed trend. |
| Scale and support path | Durable jobs/outbox, source health, usage/audit/feedback, provider configuration, documented PostgreSQL/worker migration | Deployed single-host SQLite prototype; no claim of distributed high availability. |
| Persistent bank entry | Dedicated Alfa-Business integration preview with a prominent business-signals entry | `/alfa-business`; genuine product summary, no simulated balances or claimed live banking connection. |
| Follow-up / alternative view | Grounded assistant, event questions, business-role view, original links, period briefs | Account required for questions and analyses; the public guest cannot spend the model budget. |
| Autonomous agent decisions | Plan → public tools → rank → retrieve → interpret → independent review → bounded repair/recheck | Expand agent runs; source discovery also adapts when a confirmed market lacks collectable coverage. |
| Traceability | Original articles, bank page/quote, profile snapshot/version, role, plans, source diagnostics, model usage, rejected drafts | Open event evidence and agent trace. Private endpoint credentials never appear in responses/exports. |
| Quality process and feedback | Useful/not-relevant feedback, source/error/usage operations, regression and live scenarios, proposed expert rubric | [QUALITY.md](QUALITY.md). The reviewed runs are examples, not a statistically established accuracy score. |
| Safe handling and approved models | Server tenant/RBAC guard, strict email gate, independent admin and guest sessions, SSRF/DNS pinning, encrypted custom keys, budget limits | Automated boundary checks and manual registration; only approved case gateway/model IDs by default. |

Additional owner requirements: English/Russian hostname/browser rules, multiple workspaces, team roles/invitations, separate operations accounts, SendPulse-branded mail, main deployment and RU mirror. Evidence and current test results are recorded in [QUALITY.md](QUALITY.md) and [DESIGN_AUDIT.md](DESIGN_AUDIT.md).
